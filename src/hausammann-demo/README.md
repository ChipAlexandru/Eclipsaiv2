# Hausammann shopping demo

`/hausammann-demo` adapts the Juliette photo-grid, touch basket, voice tools, and pickup preview to Bäckerei Hausammann (Zopf-Beck). It is a local demonstration; no order, reservation, payment, or store message is created.

## Public-source coverage

The catalogue was extracted on 19 September 2026 from Hausammann's official public [bread](https://www.zopfbeck.ch/pro.bro), [patisserie](https://www.zopfbeck.ch/pro.pat), [traiteur](https://www.zopfbeck.ch/pro.tra), [confiserie](https://www.zopfbeck.ch/pro.con), and [glacerie](https://www.zopfbeck.ch/pro.gla) pages. Each of the 41 included cards has a photographed product, a local image copy, and a source URL in `catalog.json`. The official [Uni 88 branch page](https://www.zopfbeck.ch/fil.uni) lists Universitätsstrasse 88, 8006 Zürich; the location is used solely for a sample pickup preview. The [official logo](https://www.zopfbeck.ch/assets/images/zopfbeck-3.ch-logo-white-dzbvz.png) is copied locally.

Coverage: 7 breads, 16 patisserie items, 9 traiteur items, 6 confiserie items, and 3 glacerie items. These are the photographed cards on those five pages, not Hausammann's full offer. One official page has two photographed cards both titled “Florentiner”; the demo retains both because the source shows them separately. Product pages may not reflect the current day, and seasonal variants may differ.

There is no verified current item price, live branch inventory, ingredient/allergen feed, payment system, or online ordering integration. Numerical CHF values are a separate deterministic **synthetic demo price dataset** in `commerce.mjs`; they are labelled synthetic wherever shown and must never be presented as official Hausammann prices. Branch stock, profile history, recommendations, options, offers, payment, orders and progress are also fictional interaction data. Official catalogue facts remain traceable to `catalog.json`. The interface does not make ingredient, allergen, or dietary assurances. Voice requires the existing server-side `OPENAI_API_KEY` Realtime setup and microphone permission. Typed input joins the same assistant only while that Realtime session is connected; without it, the field is explicitly a local catalogue search. Touch shopping and local search work without either.

## Illustrative pickup journey

The opening screen shows the active demo customer profile, its category-specific percentage offer, a shortcut to eligible products, and the selected pickup branch/time above the full photographed catalogue. The same controls and offer state appear in the basket. Shoppers can open pickup choices before adding an item; confirmation remains disabled until the basket and sample availability are valid. A confirmed preview exposes its progress tracker from the opening screen.

The basket review lets a shopper choose a fictional customer profile, sample branch, and future pickup time in the Europe/Zurich timezone. It offers every quarter-hour time from 08:00 to 16:45 across three future demo dates, subject to a 45-minute illustrative preparation lead. Branch-specific sample stock and item/slot limits can block adding or confirmation and suggest another branch/time. Existing basket lines are revalidated after branch changes. The sample bread-lover profile offers 10% off eligible bread items; the sample lunch-visitor profile offers 15% off eligible traiteur items. The UI shows synthetic list price, eligibility and indicative single-item effective price before adding. Exact basket savings round to the nearest rappen and are capped at CHF 12.00. These values and rules are invented only for the demo.

Touch, typed catalogue search, and voice use the same visible catalogue, selected product/options, basket, profile, branch and pickup state. Product-photo taps open official catalogue descriptions plus clearly marked demonstration options. Variant identity is retained as a distinct basket line. Any basket, option, profile, branch, time, sample price or stock change expires the exact review. Each prepared review receives a unique approval token, binds to a content fingerprint, and expires after two minutes. Confirmation is a two-step review then explicit approval flow; voice can approve only with that bound token after clear shopper intent. A token can be consumed once, while an identical later reorder can receive a fresh token and be approved. The resulting payment and order are simulated.

Confirmed sample orders are stored locally with a versioned schema and isolated by fictional profile. Each accepted approval token produces a distinct sample pickup code, with collisions checked against the profile's stored orders. The code and simulated Received → Preparing → Ready state survive basket changes and page reloads. The Orders view can rebuild a basket, but reorder always rechecks current sample stock, prices, options and offers and requires a new review and approval. Local storage contains only fictional demo state. Delivery remains out of scope.

Run `node scripts/extract-hausammann-catalog.mjs` to refresh the photographed subset and downloaded images. Review source changes before using an updated catalogue; the extractor follows the official site's current Mobirise card markup.

## Public deployment

Available without a password at `https://www.eclipsai.com/hausammann-demo`. Vercel deployments disable voice in both the page and token route, regardless of any shared `OPENAI_API_KEY`. Local development can still use the existing voice setup. Touch shopping and catalogue search remain available. All checkout/order state stays in the browser; no real payment or fulfilment integration is connected.
